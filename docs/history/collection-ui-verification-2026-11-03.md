# 수집 화면 빌드·검토·테스트·실행 확인 결과

수집 화면은 게임에서 시나리오와 조건을 고르고 수집을 시작·종료하는 화면이다. 빌드와 기본 수집 흐름을 확인했다. 시야 상실 시나리오의 시간 초과, 선택 목록의 낮은 글자 대비와 일부 검사 실패가 남아 있다. 전체 통과나 제품 완료 판정은 아니다.

## 1. 이번에 확인한 기능

2026-11-03 사용자가 빌드·검토·테스트·실행 확인을 명시적으로 요청했다. 이 요청에 한해 기존 구현 전용 방식에서 실행 확인까지 범위를 넓혔다.

- 원본 Editor 빌드와 새 준비 빌드의 Editor·Development Game 빌드가 성공했다. 게임 자료 변환과 배치도 성공했다.
- 별도 AI가 수집 화면 전체를 읽기 전용으로 검토했다. 부모가 수정과 실행을 맡았다.
- 실제 Development Game 창에서 조건 선택, 기본값 복원, 자동 시작, 같은 조건의 다음 회차, 진행 중 중단과 최종 목록 저장을 확인했다.
- `F8`, `Esc`, 닫기 버튼과 저장 위치 복사를 확인했다. 닫기 뒤 이동 입력으로 플레이어가 움직이는 것도 확인했다.
- 같은 준비 빌드를 세 번 실행했다. 매번 새 실행 번호와 새 세션 번호를 사용했다.
- 자동 입력용 실행에서 직접 플레이 시작은 비활성화됐다. 자동 조작 결과는 모두 자동 출처로 저장됐다.

화면 확인은 에디터 안의 PIE가 아니라 별도 Development Game에서 수행했다. 화면 없는 Unreal 내부 검사와 실제 창 조작을 서로 다른 증거로 보존했다.

## 2. 실제 수집 결과

세 세션의 네 회차에서 판단 기록 10개를 저장했다. 정상 완료, 시간 초과와 요청 중단을 구분한다.

1. **소리만 듣기:** 400cm·0도·seed 0으로 두 회차를 정상 완료했다. 판단 기록 4개를 저장했다. 첫 회차 뒤에는 다음 버튼을 누를 때까지 대기했다. 다음 회차도 같은 조건을 사용했다. 회차 한도 뒤 다음 버튼은 비활성화됐다.
2. **발소리·등장·시야 상실:** 400cm·0도·seed 1로 실행했다. 세 사건 중 발소리와 등장까지 관측했다. 시야 상실은 제한 시간 안에 관측하지 못했다. 회차는 `timed_out / event_timeout`으로 종료됐다. 판단 기록 5개와 실패한 회차의 최종 목록을 보존했다.
3. **진행 중 중단:** 같은 시야 상실 시나리오를 400cm·0도·seed 0으로 시작했다. 진행 중 종료 버튼을 눌렀다. 회차는 `cancelled / stop_requested`로 종료됐다. 판단 기록 1개와 최종 목록을 저장했다.

세 실행기는 최종 목록을 확인하고 종료 코드 0을 반환했다. 이 종료 코드는 저장과 연결 종료의 결과다. 두 번째 시나리오의 성공을 뜻하지 않는다. 화면의 오류 기록 수 0도 회차 시간 초과가 없었다는 뜻이 아니다.

최종 목록, 연결된 Capture와 저장 완료 표식의 크기·내용 식별값을 실제 파일과 대조했다. 세션·회차 파일도 같은 방식으로 대조했다. 이것은 저장 연결 확인이며 정답 판정이나 학습 승인 검사가 아니다.

## 3. 검토 중 수정한 동작

- 지역 변수 이름 충돌로 발생한 첫 컴파일 오류를 수정했다.
- 화면을 닫을 때 기존 마우스 캡처·잠금·입력 무시·커서 숨김 설정을 복원하도록 수정했다.
- 시작 전 실행기 연결 오류를 대기 상태로 숨기지 않도록 수정했다.
- 화면형 자동 수집은 회차 저장 뒤 다음·종료 버튼을 기다리도록 수정했다. 화면을 쓰지 않는 기존 자동 실행은 유지했다.

다른 메뉴의 전체 focus 복원과 시작 전 연결 단절의 실제 화면 재현은 이번 창 조작에서 확인하지 않았다. 읽기 전용 검토의 지적과 부모의 수정·실행 결과를 독립 최종 승인으로 확대하지 않는다.

## 4. 테스트 결과

- 실행기·목록·화면 대기 정책 검사 **11개 통과**.
- Unreal 내부 PlaySession 검사 **30개 중 29개 통과, 1개 실패**. 경고 이벤트 5개가 있다.
- 실패한 검사는 파일·폴더 점유 중 쓰기·삭제·이름 변경 차단을 확인한다. 별도 Windows 관측에서는 파일 접근이 오류 32로 차단됐고 폴더 이름 변경은 오류 5로 차단됐다. 기존 검사는 폴더에도 오류 32만 기대한다. 하위 관측의 성공을 Unreal 검사 성공으로 바꾸지 않았다.
- 추가로 실행한 과거 LiveCoding 검사 **16개는 공통 정상 입력 비교에서 실패**했다. 과거 예상값과 현재 빌드 계획의 `link_basis` 값이 다르다. 뒤의 개별 변이 사례까지 통과한 것으로 집계하지 않았다.

기존 검사와 저장 계약을 고쳐 통과시키지 않았다. 실패 로그를 그대로 보존했다.

## 5. 남은 문제와 확인 범위

- **시야 상실 실행:** 마지막 사건을 관측하지 못한 원인 조사와 수정이 남아 있다. 이번 실행에서는 제한 시간을 늘리거나 NPC·맵 배치를 변경하지 않았다.
- **선택 목록 가독성:** 펼친 목록의 비선택 항목이 어두운 배경에 검은 글자로 표시된다. 선택 동작은 실행됐지만 글자 대비는 보완해야 한다.
- **검사 실패:** 위의 Unreal 검사 1개와 과거 계획 검사 16개의 기대값·현재 계약 정리가 남아 있다.
- **사람 직접 플레이:** 사람 입력용 시작과 실제 사용자 플레이는 확인하지 않았다. 자동화로 사람 입력 증거를 만들지 않았다.
- **조건 범위:** 600cm와 seed 2는 선택 표시와 기본값 복원만 확인했다. 전체 실행 조합, 별도의 발소리·등장 시나리오 완료와 대량 반복 수집은 확인하지 않았다.
- **학습 연결:** 태스크 4의 수집 자료 가져오기, 정답 승인, 자료 확대와 모델 학습은 후속 구현이다.

`production collection closed`, `ResolvePolicyReady=false`, `production_eligible=false`를 유지한다.

## 6. 보존과 게시 상태

- 첫 화면 세션의 기존 파일 26개는 이후 실행 뒤에도 내용이 같았다.
- 원본 프로젝트의 보호 대상 Capture 파일 3개와 이전 준비07의 사전 목록에 있던 파일 20개를 다시 대조했다. 모두 내용이 같았다.
- 새 준비 완료 기록도 바뀌지 않았다.
- 마지막 Game은 수집 종료 뒤 결과 화면으로 남겼다. 실행 중인 수집은 없다. 다시 사용할 때는 현재 프로세스를 확인한다.
- 확인 작업 당시에는 commit/push, Shipping, 관리자 실행과 기존 자료 삭제를 수행하지 않았다. 이후 사용자 요청으로 이 기록을 Git에 게시한다. 현재 게시 범위와 로컬에 남은 소스는 [로컬 작업 인계](local-development-handoff-2026-11-03.md)에서 구분한다.
